# docs/linux — Linux & Kernel Internals

Loaded only when working under `docs/linux/`. Site-wide rules (commits, rtk, build gate, figures) are in the root `CLAUDE.md`.

A plugin-backed section with its own validation and tooling, built in phases. Phase 1a delivered the infrastructure and a 46-page scaffold. Phase 1b wrote folders `00`–`04` and CS backfill 1/2/17 (`privilege-levels-and-protection.md`, `exceptions-traps-and-interrupts.md`, `os-structure-monolithic-microkernel-hybrid.md`). Phase 2 wrote folders `05`–`10` (76 pages) and CS backfill 3/4/6/7/8/10 (memory ordering, hardware atomics, the TLB, cache coherence, NUMA, interrupt controllers), bringing the section to 123 written pages. Phase 3 wrote folders `11`–`13` (36 pages: VFS, block layer, networking) and CS backfill 12–16 (RAID, crash consistency, the sockets API, ARP/ICMP, NAT theory), bringing the section to 159 written pages. Phase 4 wrote folders `14`–`16` (37 pages: drivers, containers and virtualization, security) and CS backfill 5/9/11/18 (hardware virtualization, PCIe, DMA/IOMMU, isolation theory), bringing the section to 196 written pages. Folders `17`–`19` remain specified only in the design spec, not on disk, so no page may link into them yet. `npm run check:linux -- --written` is the gate, now covering folders 00–16. Lab sources live in `static/code/linux/<lab>/`, and pages embed them verbatim (linked with `pathname:///code/linux/...`), so the page and the code that ran can't drift. Read `docs/superpowers/specs/2026-08-28-linux-kernel-docs-design.md` for the full design; this is the operational summary.

- **The prerequisite graph is enforced, not decorative.** Every doc under `docs/linux/` must carry a `prerequisites: []` front-matter key (empty array is fine, a missing key is not). `src/plugins/knowledge-graph-plugin.js` calls the pure `buildGraph()` in `src/plugins/knowledge-graph/buildGraph.js` at build time and **fails the build** on a missing key, an unresolvable prerequisite/related id, or a dependency cycle — the same `onBrokenLinks: "throw"` philosophy applied to the knowledge graph instead of links. The graph is published as global data under the key `"knowledge-graph-plugin"`, read via `usePluginData("knowledge-graph-plugin")`.
- **A doc's real `id` strips its numeric folder prefix; `node.folder` does not.** Docusaurus's default `numberPrefixParser` strips a leading `NN-` from *both* file and folder path segments when computing a doc's `id`/URL slug — so a page physically at `docs/linux/04-kernel-architecture-and-idioms/x.md` has real id `linux/kernel-architecture-and-idioms/x`, **not** `linux/04-kernel-architecture-and-idioms/x`. A `prerequisites`/`related` front-matter value must use the *stripped* form (it's a doc-id reference) or `buildGraph` rejects it as unresolvable. But `node.folder` in the published graph (from `buildGraph.js`'s `folderOf()`) is derived from the *physical* `sourceDirName`, which keeps the numeric prefix — so a folder-granularity consumer of the published graph data would need the prefixed form (`"04-kernel-architecture-and-idioms"`), unlike `id`/`prerequisites`/`related`. These are two different fields with opposite prefix behavior; don't "fix" one to match the other. (No current component actually reads `node.folder` — see the `KnowledgeGraph` removal note below — but `buildGraph.js` still computes and publishes it.)
- **A dozen MDX components are registered globally** (`src/theme/MDXComponents.js`) for use in any `docs/linux/` page with no import: `Src` (pinned kernel source links, version lives once in `customFields.linuxKernelVersion`), `KernelFacts` (the fixed closing card — Structure/Path/Observe/Trap), `Lab` (hands-on block, throws on an unrecognized `host`), `Video`, `Cast` (asciinema player — dynamically imported inside a `useEffect`, since the library touches `document` at import time; only its CSS is a static import), `LearningPath` (renders one ordered, numbered, clickable route through the section from an explicit list of steps), `Figure` (the on-page image credit required by the Figure policy below), `WaveDrom` (timing-diagram fences), `Recall`, `Icon` (an offline, build-time SVG icon renderer, defined inline in `MDXComponents.js` rather than imported), and Docusaurus's own `Tabs`/`TabItem` re-exported for use with no import. A thirteenth, `PrereqBlock`, is not MDX-registered — it's injected directly by the swizzled `src/theme/DocItem/Layout/index.js` (before/after the article body) and returns `null` for any doc outside `docs/linux/`. **`KnowledgeGraph` was removed** in Phase 1b — the `knowledge-graph-plugin` still builds the graph and still fails the build on a missing/unresolvable/cyclic `prerequisites` entry, but the graph is no longer *drawn*. `roadmap.md` presents curated learning paths via `<LearningPath>` instead, and `PrereqBlock` (above) remains the per-page surface of the same underlying graph data.
- **Cast policy:** `<Cast>` is for sessions where the interaction *is* the lesson — a `gdb`, `bpftrace`, or `perf` session. Ordinary command-and-output material is an annotated ` ```text ` code block instead, and every cast is accompanied by one of those anyway. `static/casts/linux/hello.cast` is a placeholder proving the player works end to end; no real casts have been recorded yet.
- **Figure policy:** `docs/linux/` is exempt from the licence-gating language in "Content architecture" above — the design spec lifts that restriction for this section — but the `static/img/linux/SOURCES.md` provenance row and the on-page `<Figure source= href= />` credit are still required, exactly as `static/img/gpu/SOURCES.md` works for the GPU section. One convention, one exception.
- **The section is manifest-driven.** `tools/linux-docs-manifest.json` is the single source of truth for the page tree (title, front matter, one-sentence stub summary); `tools/scaffold-linux-docs.mjs` turns it into stub `.md` + `_category_.json` files and never overwrites an existing page without `--force` (`_category_.json` files ARE always regenerated — they're manifest-owned, not author-owned). `tools/check-linux-docs.mjs` is the authoring-convention gate the plugin can't express: category descriptions, required front-matter keys, and — for any page whose `:::info[Not yet written]` stub marker is gone — a closing `<KernelFacts />` and a `## References` section. Run `npm run check:linux` after writing a real page.
- **`.mjs` test files** (`scripts/*.test.mjs`) use `node --test` and need `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON` (no `"type"` field in `package.json`, so Node warns on ESM syntax without it) — see `test:kernel-source`/`test:graph` in `package.json` for the exact invocation.

## Working here cheaply

- Start from `tools/linux-docs-manifest.json` for the page tree instead of listing folders.
- Read only the pages named in a new page's `prerequisites`/`related` — not whole sibling folders.
- Gate: `npm run check:linux -- --written`, then `npm run build`.
