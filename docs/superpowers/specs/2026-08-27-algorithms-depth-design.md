# Design: Algorithms & Data Structures — depth, completion, and a recall layer

## Goal

Take `docs/computer-science/algorithms/` from 34 pages that cover the classics to **76 pages that
cover the field** — 75 across eight folders plus the section's own `intro.md` — and add a
consistent recall layer so a reader who has read a page once can reconstruct it from the top of the
page in about five seconds.

Two deliverables, one pass:

1. **Completion** — 42 new pages covering everything a working engineer is expected to know and
   that the section does not currently mention: union-find, tries, segment trees, probabilistic
   structures, MST, SCC, network flow, non-comparison sorts, quickselect, prefix sums, monotonic
   stacks, sweep line, string matching, number theory, amortized analysis, the master theorem, P vs
   NP.
2. **Recall** — a fixed `<Recall>` card at the top of every page, a worked trace on a small
   concrete input in every mechanism section, and five folder-level cheat-sheet pages built to be
   read on their own.

## Precedent

`docs/embedded/` (105 pages across two phases, specified in
`2026-08-18-embedded-systems-docs-design.md` and delivered through
`.superpowers/sdd/2026-08-18-embedded-phase-*/`) defines how large documentation batches are run in
this repo: a shared `house-style.md`, one brief per task carrying a page table, a ledger recording
rulings, and a build gate per task.

Three deliberate departures, based on reviewing what that phase actually produced:

1. **No task reports.** Phase 2 produced 3,632 lines of brief-and-report, of which ~2,700 were
   reports read exactly once. Replaced by a ≤25-line receipt appended to the ledger.
2. **An executable gate.** Embedded prose could only be checked by a human against a datasheet.
   Algorithm pages carry runnable code, so `tools/check-algo-docs.mjs` runs every Python block and
   syntax-checks every C++ block in addition to the structural checks.
3. **A different fact contract.** Embedded briefs demanded a datasheet section number for every
   number. Algorithm briefs demand: every complexity claim names its operation *and* its case
   (best / average / amortized / worst); anything non-obvious cites CLRS or Sedgewick by chapter or
   section; every stdlib guarantee cites the language's own documentation, never memory.

## Decisions taken

| Decision | Choice |
|---|---|
| Placement | Existing `docs/computer-science/algorithms/`; six folders extended, two added |
| New folders | `strings-and-text/`, `math-and-number-theory/` |
| Recall layer | `<Recall>` MDX card at the top of every page + 5 folder cheat sheets |
| Second recall device | A worked trace on one small concrete input in every mechanism section |
| Existing pages | All 34 get the card and a trace; 8 thin ones are rewritten to the bar |
| Code languages | Python + C++ in `<Tabs groupId="code-lang">` — unchanged from the existing pages |
| Figures | Wikimedia Commons first, `tools/figures/kbstyle.py` generated second, Mermaid only for structural content |
| Image budget | +2 MB maximum over the current 5.8 MB in `static/img/cs/` |
| Duplication | Bit tricks and integer overflow stay owned by `docs/computer-science/bit-manipulation/`; algorithm pages link to it |
| Gate | `npm run build` (throws on broken links) + `tools/check-algo-docs.mjs` + `npx biome check` on touched paths |
| Delivery | Hybrid: exemplars written by the controller, folder batches by subagents, every diff reviewed before commit |

## Non-goals

- No new top-level section, no navbar change, no sidebar hand-editing — the folders are
  autogenerated from disk.
- No interview-prep framing, question banks, or company-specific material anywhere in the content.
  Pages are written for an engineer doing the work.
- No language beyond Python and C++, and no new Prism language registration.
- No rewrite of the 25 existing pages that already meet the bar — they gain the card and a trace.

## The `<Recall>` component

New file `src/components/Recall.jsx`, registered in `src/theme/MDXComponents.js` beside `Figure`,
styled in `src/css/custom.css`.

### Contract

```jsx
<Recall
  invariant="Every parent outranks its children; the tree is complete."
  costs={[
    ["peek", "O(1)"],
    ["push / pop", "O(log n)"],
    ["build from n", "O(n)"],
    ["find arbitrary", "O(n)"],
  ]}
  reachFor="You only ever need the extreme: k-th largest, next event, Dijkstra's frontier."
  trap="Python's heapq is min-only and has no reverse= — negate, or wrap with inverted comparison."
/>
```

| Prop | Type | Required | Renders as |
|---|---|---|---|
| `invariant` | string | yes | One line. The property that must hold; the thing worth memorising. |
| `costs` | array of `[label, complexity]` | yes | Two-column monospace grid, complexities right-aligned |
| `reachFor` | string | yes | The recognition signal — what a problem looks like when this is the answer |
| `trap` | string | yes | The single classic bug, named specifically |

Rules the component enforces by shape, not by validation: four rows, no more. A fifth idea belongs
in the body. `costs` carries at most six rows; a structure needing more has a comparison table
further down the page.

### Styling

- Bordered card, accent left border, `var(--ifm-color-primary)` label column.
- Complexities in the monospace family already used by code blocks so they scan as code.
- Light/dark aware through existing Infima CSS variables — no hard-coded colours.
- Prints legibly: no background-dependent contrast, no colour-only meaning.
- Collapses to a single column below 480 px.

## Page template

Every page — new, rewritten, or amended:

```
frontmatter: id, title, sidebar_label, sidebar_position, tags
# H1 (matches title exactly)
<Recall … />
2–3 paragraphs of mental model — what problem this solves and why it behaves as it does.
  Never opens with code, a definition list, or a table.
:::info[Prerequisites]     ← only where the page genuinely depends on an earlier one
## Core Concepts           ← term table
## Mechanism               ← the figure, then the worked trace, then <Tabs> Python | C++
## Practical Usage         ← stdlib names, real call sites, what to actually type
## Edge Cases & Pitfalls   ← named failures, each with the symptom it produces
## Comparisons             ← "versus the alternative" table
## References              ← 2–6 annotated sources; what you would find in each
## Related Pages           ← 3–5 relative links, each with an em-dash reason to click
```

Target length 200–300 lines. Below 150 the page is a stub; above 340 it is two pages.

### The worked trace

The second recall device, and the requirement most likely to be skipped: every `## Mechanism`
section traces the algorithm step by step on one small concrete input, showing the state that
changes after each step.

```text
heapq.heappush on [5, 1, 8, 3] → push 0

  step  array               action
  0     [1, 3, 8, 5]        start (already a valid min-heap)
  1     [1, 3, 8, 5, 0]     append at the end — shape preserved, order broken
  2     [1, 0, 8, 5, 3]     0 < 3, swap with parent at index 1
  3     [0, 1, 8, 5, 3]     0 < 1, swap with parent at index 0 — now at the root, stop
```

Traces are `text` code blocks or generated figures, not prose. The same input is reused across
related pages wherever it makes sense (`[5, 1, 8, 3]` for heap and sort pages, one shared 6-node
graph for graph pages) so the reader compares algorithms rather than re-reading inputs.

## Tooling and gates

### `tools/check-algo-docs.mjs` — new

Run per folder. Exits non-zero on any finding.

Structural checks, per page:

- frontmatter carries `id`, `title`, `sidebar_label`, `sidebar_position`, `tags`
- a `<Recall` element exists, before the first `##`
- `## References` and `## Related Pages` exist
- at least one visual anchor: `<Figure`, a `mermaid` fence, or a `text` trace block
- line count within 150–340, except `cheat-sheet.md` pages, which are exempt in both directions —
  they are reference tables, not prose
- no duplicate `sidebar_position` inside a folder

Executable checks:

- every `python` fence is extracted and run. A fence whose first line is `# doc:no-run` is skipped
  and counted. Fences are concatenated per page in document order, so a later fence's assertions
  exercise the functions an earlier fence defined. A page that contains at least one runnable
  `python` fence must execute at least one `assert`; a page with no runnable fence — cheat sheets,
  and prose pages such as `p-np-and-intractability.md` — is exempt.
- every `cpp` fence is concatenated with its includes and compiled with
  `g++ -fsyntax-only -std=c++20`, when `g++` is present; skipped with a warning when it is not.

### Existing gates

- `npm run build` — `onBrokenLinks: "throw"`, and 41 new pages means many new relative links. Run
  after every folder batch, not only at the end.
- `npx biome check` on the touched paths only. Repo-wide `npm run lint` fails on a documented
  pre-existing baseline in unrelated files.
- `npm run typecheck` after the `<Recall>` component lands.

## Delivery

Working files live in `.superpowers/sdd/2026-08-27-algorithms-depth/`: `house-style.md`, one brief
per folder, and `progress.md` as the ledger.

| Phase | Owner | Output |
|---|---|---|
| 1 | controller | `Recall.jsx`, MDXComponents registration, CSS, `tools/check-algo-docs.mjs`; typecheck and build green |
| 2 | controller | Three exemplar pages — `data-structures/union-find.md`, `problem-solving-patterns/prefix-sums-and-difference-arrays.md`, `strings-and-text/kmp-and-z-algorithm.md` — one per page shape |
| 3 | controller | `house-style.md` plus eight folder briefs, written against the exemplars |
| 4 | subagents | One batch per folder; controller reviews every diff, runs the gate, commits |
| 5 | controller | Five cheat sheets, `algorithms/intro.md`, cross-link pass, whole-branch build |

Batch order, chosen so that a page is never written before the page it links to:
`complexity` → `data-structures` → `sorting` → `searching` → `graph-algorithms` →
`strings-and-text` → `math-and-number-theory` → `problem-solving-patterns`.

Commits: one per folder batch or smaller, `docs:` or `feat:`, one line, no trailers, per
`CLAUDE.md`.

Ledger discipline, carried over from the embedded phases: when a brief and reality disagree, the
ledger records a **Ruling** — what was decided, why, and the cost if the ruling is wrong. Each
completed batch appends a receipt of 25 lines or fewer: files, line counts, figures added with
provenance, gate results, and anything left open.

## Risks

| Risk | Mitigation |
|---|---|
| 42 new pages of relative links break the build late | Build after every batch; the batch order front-loads link targets |
| Subagent pages drift from the exemplars | Briefs carry the page table and the fact contract; every diff is reviewed before commit |
| Commons lacks a good figure and a Mermaid box diagram gets substituted | Briefs name the required visual per page and its source class; a missing Commons figure means *generate*, never downgrade |
| Image budget blown by animations | 400 KB per animation, +2 MB total, checked at the end of each batch |
| A wrong complexity claim ships | Every claim names its operation and case; non-obvious ones cite CLRS or Sedgewick by section; the reviewer re-derives rather than trusts |
| The `<Recall>` card becomes a dumping ground | Four props, fixed shape; a fifth idea goes in the body |
