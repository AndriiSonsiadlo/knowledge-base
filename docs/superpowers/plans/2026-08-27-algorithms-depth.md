# Algorithms Depth & Recall Layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take `docs/computer-science/algorithms/` from 34 pages to 76 — 42 new pages plus a `<Recall>` card and a worked trace on every page — so a reader who has read a page once can reconstruct it from the top of the page in about five seconds.

**Architecture:** One small React component (`<Recall>`) and one Node gate script (`tools/check-algo-docs.mjs`) land first; everything after that is Markdown written against three controller-written exemplar pages. Content is delivered folder by folder in an order chosen so a page is never written before the page it links to. Every batch ends with the gate green and one commit.

**Tech Stack:** Docusaurus 3.9 Markdown (MDX), React 19 for `<Recall>`, Tailwind-free plain CSS in `src/css/custom.css`, Mermaid, the existing `<Figure>` / `<Tabs>` MDX components, `tools/fetch-commons.mjs` for Wikimedia figures, `tools/figures/kbstyle.py` (matplotlib) for generated figures, `g++` and `python3` for the executable gate.

**Spec:** `docs/superpowers/specs/2026-08-27-algorithms-depth-design.md` — read it before starting. Its page-inventory tables are the source of truth for page content; this plan carries the same tables per task so an executor never needs the whole spec at once.

**Model note:** this plan is written to be executed by Sonnet 5. Every task states the exact files, positions, gate commands, and commit message. Nothing is left to taste except the prose itself.

## Global Constraints

Copied from the spec, plus values verified against the repository on 2026-08-27. Every task's requirements implicitly include this section.

- **Root:** `docs/computer-science/algorithms/`. Eight folders after this plan: `complexity` (position 1), `data-structures` (2), `sorting` (3), `searching` (4), `graph-algorithms` (5), `problem-solving-patterns` (6), `strings-and-text` (**7, new**), `math-and-number-theory` (**8, new**).
- **No structural changes outside the section.** No navbar edit, no `sidebars.js` edit, no new top-level section, no new dependency, no new Prism language. Sidebars are autogenerated from disk.
- **`_category_.json`** — 2-space indent, keys `label`, `position`, `link.type = "generated-index"`. Exactly two new ones (Tasks 16 and 17).
- **Frontmatter** — every page carries `id`, `title`, `sidebar_label`, `sidebar_position`, `tags`. `id` is the filename without `.md` except for `intro.md` pages, which use `<folder-slug>-intro` (existing convention: `complexity-intro`, `data-structures-intro`, `sorting-intro`, `searching-intro`, `graph-algorithms-intro`, `patterns-intro`; new: `strings-intro`, `math-intro`). `tags` starts `[computer-science, algorithms, ...]`.
- **Page template** — every page, new or amended:

  ```
  frontmatter
  # H1 (matches `title` exactly)
  <Recall … />
  2–3 paragraphs of mental model — the problem this solves and why it behaves as it does.
    Never opens with code, a definition list, or a table.
  :::info[Prerequisites]     ← only where the page genuinely depends on an earlier one
  ## Core Concepts           ← term table
  ## Mechanism               ← the figure, then the worked trace, then <Tabs> Python | C++
  ## Practical Usage         ← stdlib names, real call sites, what to actually type
  ## Edge Cases & Pitfalls   ← named failures, each with the symptom it produces
  ## Comparisons             ← "versus the alternative" table
  ## References              ← 2–6 annotated sources; what you would find in each
  ## Related Pages           ← 3–5 relative links, each with an em-dash reason to click
  ```

  Existing pages use `## Architecture / Mechanism` for the mechanism heading. Both spellings are accepted; do not rename headings on amended pages just to match.
- **Length** — 150–340 lines, enforced by the gate. `cheat-sheet.md` pages are exempt in both directions. Below 150 is a stub; above 340 is two pages.
- **Code** — Python and C++ only, in `<Tabs groupId="code-lang">` with `<TabItem value="python" label="Python">` and `<TabItem value="cpp" label="C++">`. Fences are ` ```python showLineNumbers ` and ` ```cpp showLineNumbers `.
  - Every `python` fence on a page is concatenated **in document order** and run by the gate. A page with at least one runnable fence must execute at least one `assert`. Put the asserts in the last fence.
  - A fence whose **first line** is `# doc:no-run` is skipped (use it for illustrative fragments, `...` placeholders, or code that needs input).
  - Every `cpp` fence is concatenated and compiled with `g++ -fsyntax-only -std=c++20`. All `#include` lines go in the page's **first** `cpp` fence. A fence whose first line is `// doc:no-run` is skipped.
- **Fact contract** — non-negotiable, this is what the reviewer checks:
  1. Every complexity claim names its **operation** *and* its **case** (best / average / amortized / worst). "O(1) amortized push", never "O(1) push".
  2. Anything non-obvious cites **CLRS 4th ed.** or **Sedgewick & Wayne 4th ed.** by chapter or section number.
  3. Every stdlib guarantee cites the language's own documentation (CPython docs, cppreference, the C++ standard) — never memory. `list.append` being amortized O(1) is a CPython implementation note; say so and link it.
- **Recall card** — exactly four props, all required: `invariant`, `costs`, `reachFor`, `trap`. `costs` is an array of `[label, complexity]` pairs, at most six. A fifth idea belongs in the body; a seventh cost belongs in a comparison table further down.
- **Worked trace** — every `## Mechanism` section traces the algorithm on one small concrete input, showing the state after each step, as a ` ```text ` block or a generated figure. Never as prose. **Shared inputs**, reused across related pages so the reader compares algorithms rather than re-reading inputs:

  | Domain | Input |
  |---|---|
  | Heaps, sorting, selection | `[5, 1, 8, 3]`; longer runs use `[5, 1, 8, 3, 9, 2, 7, 4]` |
  | Prefix sums, sweep, monotonic stack | `[3, 1, 4, 1, 5, 9, 2, 6]` |
  | Undirected weighted graph (MST, Dijkstra, traversal) | 6 nodes `A B C D E F`; edges `A–B 4, A–C 2, B–C 1, B–D 5, C–D 8, C–E 10, D–E 2, D–F 6, E–F 3` |
  | Directed graph (topological sort, SCC, cycles) | `A→B, B→C, C→A, B→D, D→E, E→F, F→D` — two cycles, one condensation DAG of three components |
  | Strings (matching) | text `abacabadabacaba`, pattern `abacaba` |
  | Modular arithmetic | `gcd(252, 198)`, `3^13 mod 7` |
- **Figures** — Wikimedia Commons first (`tools/fetch-commons.mjs`), `tools/figures/gen_algorithms.py` second, Mermaid only for genuinely structural content (decision flows, family maps, the condensation-DAG concept). ## Content task recipe

Tasks 6–21 all write Markdown. There is no red/green test cycle for prose; the equivalent feedback loop is **write → gate → fix → commit**. Every content task follows exactly these steps. They are not repeated in each task; each task states only what is specific to it.

1. Read `.superpowers/sdd/2026-08-27-algorithms-depth/house-style.md`.
2. Read the exemplar named in the task ("Exemplar:" line). Match its density, its voice, and its section order. Do not read all three exemplars — one is enough and the other two cost tokens.
3. For each page in the task's table, in the order given:
   - Write the frontmatter with the exact `id`, `title`, `sidebar_label`, `sidebar_position` from the table.
   - Write the `<Recall>` card: one-line `invariant`, ≤6 `costs` rows each naming operation and case, a `reachFor` that describes what the *problem* looks like, and a `trap` that names one specific classic bug.
   - Write the body to the page template in Global Constraints.
   - The `## Mechanism` section gets the required visual from the table, then the worked trace on the table's trace input, then the `<Tabs>` code.
   - Every complexity claim names operation and case. Non-obvious claims cite CLRS or Sedgewick by section. Every stdlib guarantee cites that language's docs.
   - `## Related Pages` links only to pages that exist on disk right now.
   **What the task tables mean:**
   - **Amend** — the page stays; add the `<Recall>` card directly under the H1, add the worked trace to its mechanism section, and do the named gap-fill. Do not restructure a page that already works.
   - **Gap-fill** — the specific missing material named in that row, plus anything the fact contract exposes as unsupported: a complexity claim with no case, a stdlib guarantee written from memory, a "roughly" where a number belongs. Not a general polish pass.
   - **Folder `intro.md` pages** — all six existing ones (`complexity`, `data-structures`, `sorting`, `searching`, `graph-algorithms`, `problem-solving-patterns`) currently have **no `## References` section** and the gate requires one. Add 2–3 annotated sources — the CLRS/Sedgewick chapters that cover the folder — to every one of them.
   - **Rewrite** — the page is rebuilt to the page template. Keep any paragraph that is genuinely good; the line count in the table tells you how far it is from the bar.
4. Run the gate:
   ```bash
   node tools/check-algo-docs.mjs docs/computer-science/algorithms/<folder>
   npm run build
   npx biome check docs/computer-science/algorithms/<folder>
   du -sh static/img/cs        # must stay under 7.8 MB
   ```
5. Fix every finding. A page that fails the length floor is under-written — add substance, never filler. A Python fence that fails either has a bug (fix the code) or is illustrative (mark it `# doc:no-run` and move the asserts to a runnable fence).
6. Append the ≤25-line receipt to `progress.md`.
7. Commit with the task's stated message.

- [ ] **Step 1: Write the checker**

`tools/check-algo-docs.mjs`:

```js
#!/usr/bin/env node
// Structural and executable gate for docs/computer-science/algorithms/.
//
//   node tools/check-algo-docs.mjs                                  # the whole section
//   node tools/check-algo-docs.mjs docs/computer-science/algorithms/complexity
//   node tools/check-algo-docs.mjs docs/.../complexity/big-o-notation.md
//
// Structural checks are cheap and always run. On top of them, every `python`
// fence on a page is concatenated in document order and executed, and every
// `cpp` fence is concatenated and syntax-checked, because a documentation page
// that ships code nobody ran is a page that ships bugs.
//
// A fence whose first line is `# doc:no-run` (python) or `// doc:no-run` (cpp)
// is skipped and counted — for illustrative fragments and code needing input.
import { spawnSync } from "node:child_process";
import { mkdtempSync, readdirSync, readFileSync, statSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { basename, dirname, join } from "node:path";

const DEFAULT_ROOT = "docs/computer-science/algorithms";
const MIN_LINES = 150;
const MAX_LINES = 340;
const FRONTMATTER_KEYS = ["id", "title", "sidebar_label", "sidebar_position", "tags"];

const findings = [];
const note = (file, msg) => findings.push(`${file}: ${msg}`);
let skippedFences = 0;

const HAS_GXX = spawnSync("g++", ["--version"], { stdio: "ignore" }).status === 0;

function collect(target) {
	const st = statSync(target);
	if (st.isFile()) return [target];
	return readdirSync(target, { recursive: true, withFileTypes: true })
		.filter((d) => d.isFile() && d.name.endsWith(".md"))
		.map((d) => join(d.parentPath ?? d.path, d.name))
		.sort();
}

function frontmatter(text) {
	const m = text.match(/^---\n([\s\S]*?)\n---\n/);
	if (!m) return null;
	const out = {};
	for (const line of m[1].split("\n")) {
		const kv = line.match(/^([A-Za-z_]+):\s*(.*)$/);
		if (kv) out[kv[1]] = kv[2].trim();
	}
	return out;
}

function fences(text, lang) {
	const re = new RegExp("^```" + lang + "[^\\n]*\\n([\\s\\S]*?)^```", "gm");
	const out = [];
	let m;
	while ((m = re.exec(text)) !== null) out.push(m[1]);
	return out;
}

function runnable(blocks, marker) {
	return blocks.filter((b) => {
		const skip = b.split("\n")[0].trim() === marker;
		if (skip) skippedFences++;
		return !skip;
	});
}

function tempFile(name, contents) {
	const path = join(mkdtempSync(join(tmpdir(), "algo-docs-")), name);
	writeFileSync(path, contents);
	return path;
}

function tail(s, n = 6) {
	return (s ?? "").trim().split("\n").slice(-n).join("\n        ");
}

// ------------------------------------------------------------------ per page
function checkPage(file, positions) {
	const text = readFileSync(file, "utf8");
	const name = basename(file);
	const isCheatSheet = name === "cheat-sheet.md";

	const fm = frontmatter(text);
	if (!fm) {
		note(file, "no frontmatter block");
	} else {
		for (const k of FRONTMATTER_KEYS) {
			if (!(k in fm)) note(file, `frontmatter missing \`${k}\``);
		}
		const pos = fm.sidebar_position;
		if (pos !== undefined) {
			const folder = dirname(file);
			const seen = positions.get(folder) ?? new Map();
			if (seen.has(pos)) note(file, `duplicate sidebar_position ${pos} (also ${seen.get(pos)})`);
			else seen.set(pos, basename(file));
			positions.set(folder, seen);
		}
	}

	const body = text.replace(/^---\n[\s\S]*?\n---\n/, "");
	const firstH2 = body.indexOf("\n## ");
	const recallAt = body.indexOf("<Recall");
	if (recallAt === -1) note(file, "no <Recall> card");
	else if (firstH2 !== -1 && recallAt > firstH2) note(file, "<Recall> card appears after the first ##");

	if (!/^## References\s*$/m.test(text)) note(file, "no `## References` section");
	if (!/^## Related Pages\s*$/m.test(text)) note(file, "no `## Related Pages` section");

	const hasVisual = /<Figure/.test(text) || /^```mermaid/m.test(text) || /^```text/m.test(text);
	if (!hasVisual) note(file, "no visual anchor (<Figure, mermaid fence, or text trace block)");

	const lines = text.split("\n").length;
	if (!isCheatSheet && lines < MIN_LINES) note(file, `${lines} lines — under the ${MIN_LINES} floor`);
	if (!isCheatSheet && lines > MAX_LINES) note(file, `${lines} lines — over the ${MAX_LINES} ceiling`);

	// --- python
	const py = runnable(fences(text, "python"), "# doc:no-run");
	if (py.length) {
		const src = py.join("\n\n");
		if (!/^\s*assert\b/m.test(src)) note(file, "runnable python fences but not one assert");
		const r = spawnSync("python3", [tempFile("page.py", src)], { encoding: "utf8", timeout: 60000 });
		if (r.status !== 0) note(file, `python fences failed:\n        ${tail(r.stderr || r.stdout)}`);
	}

	// --- c++
	const cpp = runnable(fences(text, "cpp"), "// doc:no-run");
	if (cpp.length && HAS_GXX) {
		const src = cpp.join("\n\n");
		const r = spawnSync("g++", ["-fsyntax-only", "-std=c++20", tempFile("page.cpp", src)], {
			encoding: "utf8",
			timeout: 120000,
		});
		if (r.status !== 0) note(file, `c++ fences failed to compile:\n        ${tail(r.stderr || r.stdout)}`);
	}
}

// ---------------------------------------------------------------------- main
const targets = process.argv.slice(2).length ? process.argv.slice(2) : [DEFAULT_ROOT];
const files = targets.flatMap(collect);
const positions = new Map();
for (const f of files) checkPage(f, positions);

if (!HAS_GXX) console.warn("warning: g++ not found — c++ fences were not syntax-checked");
console.log(`${files.length} pages checked, ${skippedFences} fences skipped via doc:no-run`);

if (findings.length) {
	console.error(`\n${findings.length} finding(s):`);
	for (const f of findings) console.error(`  ${f}`);
	process.exit(1);
}
```
