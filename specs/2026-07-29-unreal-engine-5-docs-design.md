# Unreal Engine 5 Documentation Section — Design Spec

**Date:** 2026-07-29
**Status:** Approved, ready for implementation planning
**Author:** brainstorming session (Opus 5) — implementation plans and doc writing delegated to Sonnet 5

---

## 1. Goal

Add an Unreal Engine 5 documentation section to this knowledge base that serves as a **mastery path for a C++-first game developer**. Reading the section front to back takes a reader from "installed the engine" to "shipped a single-player 3D game, with the codebase ready for a later multiplayer retrofit".

The section must also work as a **reference** afterwards: each folder is one engine subsystem, each page answers one question.

### Success criteria

1. A reader with solid C++ but zero Unreal experience can follow folders `00` → `18` and never hit an unexplained prerequisite.
2. Every engine-specific API claim is traceable to official UE 5.7 documentation.
3. `npm run build` passes after every tranche (`onBrokenLinks: "throw"` makes broken links a deploy failure).
4. The section reads like the existing `docs/programming/boost` section — same frontmatter, same admonition and mermaid usage, same prose register.

### Non-goals

- Not a game design or art-direction guide.
- Not a replacement for Epic's API reference — this explains *how systems fit together and why*, and links out for exhaustive signatures.
- No console platform coverage (PlayStation/Xbox/Switch) — NDA-gated and unavailable.
- No Unreal Engine 4 migration content.

## 2. Facts, assumptions, unknowns

### Facts (verified this session)

- Repo is Docusaurus 3.9. Five autogenerated sidebars in `sidebars.js`, each bound to one top-level folder under `docs/`.
- `docs/programming/boost` is the structural precedent: 17 numbered folders, `_category_.json` per folder (`label`, `position`, `link: generated-index`), doc frontmatter of `id` / `title` / `sidebar_label` / `sidebar_position` / `tags`.
- Existing docs use 2117 ` ```cpp ` fences, 193 ` ```mermaid ` fences, and Docusaurus admonitions.
- `prism.additionalLanguages` in `docusaurus.config.js` is currently `["bash", "cmake"]`.
- Context7 exposes official UE docs as `/websites/dev_epicgames_unreal-engine` — "Unreal Engine 5.7 Documentation", 145,103 code snippets, High source reputation. Secondary: `/mrrobinofficial/guide-unrealengine` (C++ and module-system guide, benchmark 57.78).

### Decisions taken by the user

- Placement: new top-level `docs/game-development/`, UE5 nested inside it.
- TOC shape: numbered subsystem folders in learning order, plus one roadmap page.
- Target: single-player 3D now, multiplayer possible later.
- Engine version: **UE 5.7**.
- Dev platform: **Windows** (Visual Studio 2022 / MSVC).
- All four heavy optional areas in scope: GAS, editor tooling in C++, rendering internals, content pipeline and audio.

### Assumptions (unverified, documented as required by this spec)

- An unknown Prism language degrades to unhighlighted plain text rather than failing the build. **Not verified in this environment.** The `csharp` / `ini` additions below are therefore a quality improvement, not a build blocker. Verify with `npm run build` when the first doc using those fences lands.
- Context7's UE 5.7 corpus covers the subsystems listed in the TOC. Coverage per subsystem has not been probed individually; the writer must confirm per topic and fall back to official docs when Context7 returns nothing useful.

### Unknowns

- Which UE 5.7 APIs changed relative to 5.6 — resolved per doc at writing time by consulting Context7, not by recall.
- Whether the reader's machine has the engine installed from the Epic Launcher or built from source. Docs default to Launcher install and call out source-build differences only where behaviour actually differs (`01-toolchain-and-build`).

## 5. Per-document contract

Every document must satisfy all of the following.

**Frontmatter**

```yaml
---
id: <kebab-case, matches filename>
title: <full title, sentence case>
sidebar_label: <short label>
sidebar_position: <ordinal within folder>
tags: [ unreal-engine, ue5, c++, <topic tags> ]
---
```

**Body structure**

1. **Why this matters** — two to four sentences of orientation. What breaks without this knowledge.
2. **Mental model** — the concept before the API. Mermaid diagram where the topic is relational (ownership, lifecycle, data flow). Prose where it is not.
3. **The mechanics** — how it works, in the engine's own terms, with correct UE 5.7 type and function names.
4. **Code** — ` ```cpp ` fences with realistic, self-consistent snippets, including the `UPROPERTY` / `UFUNCTION` specifiers that a real file needs. `csharp` fences for `Build.cs`, `ini` for config.
5. **Gotchas** — `:::warning` / `:::caution` admonitions for the traps. This is where the section earns its value over the official docs.
6. **See also** — relative links to sibling docs (`./other-doc.md`, `../03-gameplay-framework/actor-lifecycle.md`) and an outbound link to the authoritative Epic page.

**Constraints**

- Relative doc links only — never absolute paths, because `baseUrl` is `/knowledge-base/`.
- Every folder gets `_category_.json` with `label` (`"NN. Title Case"` — matching the boost convention), `position`, and `link: { "type": "generated-index" }`.
- Prose register matches `docs/programming/boost`: explanatory, second person, no marketing tone, no filler.
- No screenshots in the initial pass. Editor-workflow steps are described in text. Images can be added later; they are not a blocker and are not fabricated.

## 6. Documentation sourcing rules

**Mandatory.** Unreal's API surface is large, versioned, and frequently changed. Recall is not an acceptable source.

Priority order for every engine-specific claim:

1. **Context7** — `/websites/dev_epicgames_unreal-engine` (UE 5.7 official, 145k snippets). Secondary for C++ and module-system specifics: `/mrrobinofficial/guide-unrealengine`.
2. Official Epic documentation and the UE 5.7 API reference.
3. Engine source (`Engine/Source/`) where the reader has it available.
4. Established community references, clearly attributed as such.
5. Model knowledge — last resort, and only for stable, long-lived concepts.

Rules:

- **Never invent an API.** No class, function, macro, specifier, or console command goes into a doc unless it was found in a source above.
- When a claim could not be verified, state it inline rather than dropping it: *"Verify against your engine version — not confirmed for 5.7 in the sources consulted."*
- Version-sensitive behaviour gets an explicit `:::note` naming the version.
- Console command and CVar names must be quoted exactly as documented.

## 7. References policy

`00-overview/learning-resources.md` collects external learning material; individual docs may add a short "further reading" line.

Every reference must be a **real, verifiable source**. No invented book titles, no plausible-looking URLs, no fabricated video links.

- Books: title, author, and edition only if confirmed. Candidates to verify before inclusion: Sharp, *Unreal Engine 5 C++ The Ultimate Developer's Handbook*; Gregory, *Game Engine Architecture*.
- Epic official learning material: link only to pages confirmed to exist.
- Community sources (Tom Looman's UE C++ material, the community GAS documentation) — include only after confirming the resource is live, and label it as community-maintained, not official.
- Any reference that cannot be confirmed is omitted. An empty section beats a fabricated citation.

## 8. Delivery plan

Four tranches. Each gets its own implementation plan and lands independently.

| Tranche | Scope | Ships when |
|---|---|---|
| **T1** | Config changes (§3) + folders 00–04, 37 docs | Reader can set up the toolchain, write correct Unreal C++, and understand the gameplay framework — enough to start the game. |
| **T2** | Folders 05–09, 26 docs | Input, physics, animation, UI, AI — a playable loop is buildable. |
| **T3** | Folders 10–12, 23 docs | GAS, world building, rendering internals. |
| **T4** | Folders 13–18, 34 docs | Audio, content pipeline, performance, networking, editor tooling, shipping. |

**Acceptance criteria per tranche**

1. All planned files exist with valid frontmatter and `_category_.json` per folder.
2. `npm run build` passes — this is the link-integrity gate, not an optional check.
3. `npm run lint` and `npm run format` clean.
4. Sidebar renders in the expected order; folder labels match the TOC.
5. Every engine-specific claim traceable to a §6 source; unverifiable claims explicitly marked.
6. No placeholder text, no "TODO", no empty sections.

**Per-tranche risks**

- *T1* — the config edits touch shared files; a malformed navbar entry breaks the whole site. Change `sidebars.js` and `docusaurus.config.js` first and build before writing any content.
- *T3* — rendering internals and GAS are the areas most likely to exceed what Context7 covers well. Where depth is unavailable, write the mental model and link out rather than guessing at API detail.
- *All* — 120 docs is a large surface for link rot between siblings. Write each folder's docs together and build at folder granularity, not just tranche granularity.

| Risk | Mitigation |
|---|---|
| Fabricated API detail — the dominant failure mode for engine docs | §6 sourcing rules are mandatory; unverifiable claims marked inline, never smoothed over |
| Scope drift toward an API-reference clone | Each doc leads with the mental model and gotchas; exhaustive signatures are linked, not copied |
